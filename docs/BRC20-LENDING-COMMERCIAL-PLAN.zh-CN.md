# BRC-20 商业借贷产品方案

> 状态：产品方案 v0.1 已确认。阶段 1 的报价向导已经实现；链上抵押、放款、还款与违约领取尚未开放。

## 1. 产品目标

让持有 BRC-20 的用户无需出售资产，也能抵押 BRC-20 借入 BTC；让持有 BTC 的用户可以发布出借报价并赚取固定利息。

首版采用：

- Bitcoin Testnet4；
- UniSat 钱包；
- 出借人先报价、借款人后接受；
- 固定本金、固定利息、固定期限；
- 到期前不做价格清算；
- 到期未还款时，出借人取得抵押品；
- 平台不保管用户私钥。

## 2. 小白看到的完整流程

### 2.1 Bob 发布出借报价

Bob 连接钱包后填写：

- 愿意借出多少 BTC；
- 接受哪一种 BRC-20；
- 需要多少 BRC-20 抵押；
- 收取多少利息；
- 贷款期限；
- 报价多久失效。

Bob 点击“发布报价”时只签署报价，不立即把 BTC 发送给 Alice。

### 2.2 Alice 选择报价

Alice 连接钱包后，页面自动读取：

- Alice 持有的 BRC-20；
- 可用余额；
- 已制作但尚未使用的 Transfer 铭文；
- 当前 BTC 手续费余额。

Alice 不需要输入 ticker、地址、公钥、铭文 ID 或 UTXO。

### 2.3 系统准备抵押凭证

如果 Alice 没有金额正好的 Transfer 铭文，系统引导她制作一张：

```text
“将 100 ORDI 变为可转移的抵押凭证”
```

用户界面只显示：

1. 准备抵押凭证；
2. 等待确认；
3. 可以开始贷款。

技术详情中的 Commit、Reveal、Inscription ID 和 Outpoint 默认折叠。

### 2.4 双方激活贷款

真正开始贷款时，系统构造一组双方核对和签署的交易：

```text
Bob 的 BTC ─────────────→ Alice
Alice 的 BRC-20 抵押凭证 → 贷款金库
```

只有本金金额、抵押数量、接收地址和金库规则全部正确，双方才签名。交易确认后贷款进入 Active。

### 2.5 两种结束结果

正常还款：

```text
Alice 支付本金 + 利息 → Bob
抵押 BRC-20          → Alice
```

到期未还款：

```text
贷款到期
Bob 通过超时出口取得抵押 BRC-20
```

每一种结果都必须提供可复制的交易链接和明确的资产去向。

## 3. 为什么 BRC-20 比 Runes 复杂

BRC-20 余额不能像普通 BTC 一样直接转账。发送 BRC-20 前，需要先创建 Transfer 铭文；每张 Transfer 铭文只能使用一次。

商业产品必须管理三种余额：

- Available：可以制作新 Transfer 铭文；
- Transferable：已经制作好、等待发送的 Transfer 铭文；
- Overall：两者合计。

产品不能只读取钱包显示的总余额，也不能重复使用已经消费过的 Transfer 铭文。

## 4. 建议的链上协议

### 4.1 报价阶段不上链

Bob 使用钱包签署结构化报价，内容包括报价 ID、BRC-20 ticker、抵押数量、本金、利息、期限、到期时间、Bob 的地址和公钥。

平台验证签名后进入报价簿。报价具有 nonce 和失效时间，防止重复接受和重放。

### 4.2 抵押准备阶段

Alice 选择报价后，系统检查是否存在金额完全匹配的 Transfer 铭文。

- 已存在：直接进入贷款预览；
- 不存在：生成 Commit/Reveal，让 Alice 制作抵押凭证；
- 金额过大：不自动拆分，先明确提示将生成新的精确金额凭证；
- 余额不足或索引器不一致：禁止继续。

### 4.3 原子激活

贷款激活交易同时使用：

- Alice 的 BRC-20 Transfer 铭文 UTXO；
- Bob 的 BTC 本金 UTXO；
- 双方各自的手续费和找零输出；
- 贷款 Taproot 金库输出；
- Alice 的本金接收输出。

目标是避免“Bob 已放款但没有抵押”或者“Alice 已交抵押但没有收到本金”。

### 4.4 抵押品退出凭证

Transfer 铭文在发送到贷款金库后已经被消费，不能直接再发送一次。协议需要在贷款金库中制作一张新的 Transfer 铭文，作为最终可以发送给 Alice 或 Bob 的抵押退出凭证。

所有依赖交易、签名和恢复数据必须在广播贷款激活交易前准备完整。任一步无法准备时，不启动贷款。

### 4.5 活动贷款金库

金库至少提供两个出口：

```text
正常出口：Alice + Bob 合作签名
           同一笔结算交易中，Bob 收到本金和利息，Alice 收回 BRC-20

违约出口：等待贷款期限结束 + Bob 签名
           BRC-20 抵押凭证发送给 Bob
```

正常还款必须与抵押品返还绑定，不能只根据页面提示或一笔独立付款判断已经还款。

## 5. 商业产品组成

### 用户端

- 出借大厅；
- 发布报价；
- 借款人资产选择；
- 逐步签名向导；
- 贷款详情和到期倒计时；
- 还款、违约领取和恢复入口。

### 协调服务

- 报价存储和撮合；
- 报价签名验证；
- 防止报价重复成交；
- PSBT 和依赖交易协调；
- 交易状态同步；
- 邮件、Telegram 或站内通知；
- 不保存助记词和私钥。

### 索引与核对

- 至少使用两个独立 BRC-20 索引结果交叉核对；
- 核对 Available、Transferable、铭文状态和 UTXO 是否已花费；
- 结果不一致时暂停签名，不猜测资产状态。

## 6. 商业收入

首版建议只收成功服务费：

- 报价和浏览免费；
- 贷款成功激活时收取平台费；
- 正常还款可从利息中按比例收取服务费；
- 违约时不额外抽走抵押品；
- 所有平台费在签名前作为明确交易输出展示。

具体比例在 Testnet4 完整测算矿工费和最小贷款金额后决定，不提前写死。

## 7. 页面设计原则

- 地址和公钥由钱包读取，不让用户填写；
- BRC-20 从钱包资产列表选择，不让用户输入 ticker；
- 铭文 ID、Outpoint、PSBT 放在“技术详情”中；
- 每个页面只要求用户完成一个动作；
- 每次签名前使用资产语言说明“你付出什么、你收到什么”；
- 当前交易未确认时，不显示下一步签名按钮；
- 用户关闭页面后可以根据 Loan ID 恢复；
- 所有失败状态都告诉用户下一步应该怎么处理。

## 8. 开发与验收顺序

### 阶段 0：协议冻结

- 完成威胁模型；
- 冻结报价结构；
- 冻结正常还款和违约脚本；
- 明确完整交易数量和依赖关系；
- 用固定测试向量证明资产不会卡死。

### 阶段 1：商业页面骨架

- Bob 发布报价；
- Alice 浏览和接受报价；
- 钱包自动读取地址和公钥；
- 不产生链上交易。

### 阶段 2：BRC-20 资产发现

- 自动显示 Alice 的 BRC-20；
- 区分 Available 和 Transferable；
- 生成精确金额 Transfer 铭文；
- 双索引器核对。

### 阶段 3：Testnet4 贷款激活

- 双方签署完整交易包；
- Alice 收到 BTC；
- 抵押进入贷款金库；
- 清除本地数据后可恢复。

### 阶段 4：还款与违约

- 正常还款闭环；
- 到期前违约领取失败；
- 到期后 Bob 领取成功；
- 同一抵押品不能同时被两种结果花费。

### 阶段 5：商业后台

- 报价簿；
- 报价占用和取消；
- 通知；
- 平台费；
- 管理后台和异常监控。

### 阶段 6：安全验收

- 独立代码审计；
- 钱包兼容测试；
- 索引器差异和区块重组测试；
- 低费率、交易卡住、断网和拒签恢复测试；
- 限额 Testnet4 公测。

主网入口只有在以上阶段全部通过后才讨论。

## 9. 当前项目处理决定

当前 Runes 页面、固定测试地址、公钥和 Rune ID 不继续扩展，也不迁移到正式页面。可以保留底层 Taproot 实验代码作为研究材料，但新的产品页面、数据模型、TRD 和验收全部以 BRC-20 为准重新设计。

## 10. 方案评审时需要确认

1. 第一版只做出借人先报价，还是同时提供借款需求单；
2. 允许抵押哪些 BRC-20 ticker；
3. 固定期限使用区块数还是自然时间展示、区块数执行；
4. 报价是否要求 Bob 预存 BTC；
5. 平台费从本金还是利息中收取；
6. 第一版最低本金；
7. 是否只支持 UniSat；
8. 采用哪些独立索引器进行交叉验证。
